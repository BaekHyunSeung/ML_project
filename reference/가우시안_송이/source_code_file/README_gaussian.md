## 실행

```bash
cd source_code_file
python 3_gaussian_model.py apartment          # 건물유형 하나
python 3_gaussian_model.py apartment hotel    # 여러 개
python 3_gaussian_model.py all                # 10개 전부 + 제출 파일 생성

# 옵션
#   --trend none|smooth|linear|v1   추세 변수 처리 (기본 none)
#   --restarts N                    커널 최적화 재시작 횟수 (기본 1, 0이면 빠름)
#   --tag 이름                      결과 폴더 model_output/<이름> (기본 gaussian)
#   --validate-only                 검증만 하고 test 예측 생략
#   --jobs N                        동시에 학습할 건물 수 (기본 CPU 코어 수)
#   --valid-start YYYY-MM-DD        검증 시작일, 이 날 0시 미만은 학습 (기본 2024-08-08 = 80/20)
```

필요한 패키지: pandas, numpy, scikit-learn, joblib (scikit-learn 설치 시 같이 들어옴)

## 모델 설계

**건물 1동 = 모델 1개.** 가우시안 프로세스는 데이터 수 n의 세제곱(n³)에 비례해 느려진다.
유형 전체(약 2만 행)를 한 번에 넣으면 메모리·시간이 감당이 안 되므로 건물마다(2,040행) 따로 학습한다.
면적, 태양광·ESS·PCS 용량은 건물 안에서 상수라 입력에서 뺀다.

**입력 (9개)**
- 날씨: temperature, precipitation, wind_speed, humidity
- 시간: hour_sin, hour_cos, weekday_sin, weekday_cos (23시→0시, 일→월이 이어지도록 주기 함수로 변환), is_off_day (주말 또는 공휴일)
- v1에 있던 day_index(추세)는 v2에서 제거
- 일조·일사는 test.csv에 없어서 제외

**출력**: power_consumption에 log1p를 씌워 학습하고, 예측 후 expm1로 되돌린다.
전력소비량은 치우친 양수 분포이고 평가지표 SMAPE가 상대 오차라서 로그 변환이 유리하다.

**커널**: `ConstantKernel × RBF(입력마다 길이척도 따로, ARD) + WhiteKernel`
- 길이척도가 크게 나오는 입력(예: 강수량 → 1e3 상한)은 모델이 거의 안 보는 변수라는 뜻
- WhiteKernel은 관측 잡음을 흡수
- 입력은 StandardScaler로 표준화, 출력은 normalize_y=True

## 상용·백화점에서 추가로 확인한 원인

- **공휴일 미반영** (상용 6·16·86동): 8/15 광복절(목)이 훈련에 들어 있어 목요일을 낮게 학습. 검증 8/22(목)을 크게 낮게 예측. `is_holiday` 변수로 해결 가능.
- **day_index 평균 회귀** (백화점 전반, SMAPE 23.7): day_index 길이척도가 8~10일로 짧게 학습되어 훈련 마지막 날 이후 예측이 전체 평균 쪽으로 매일 내려간다. 실제는 평평한데 예측만 하락. test 기간도 같은 조건이라 **가장 먼저 고쳐야 할 문제**. day_index 제거 또는 DotProduct 커널 추가 / 길이척도 하한 30일.
- **월 1회 정기 휴무일** (백화점): 날짜가 건물마다 달라 예측 불가. 모든 모델이 공통으로 틀리는 부분.

## 개선 아이디어

- `N_RESTARTS`를 2~3으로 올리면 커널 최적화가 안정되지만 시간이 배로 든다
